L2 · Subsystem · Part of MarDoc architecture (L1, as-is)

Repository browsing: the tree opens collapsed and remembers what you opened

Implements: the repository, branch and file navigation of the L1 App shell card. As-is, every folder at depth 0 and 1 opens expanded and the choice is never kept. Issue #151 adds one pure module and one small storage adapter to fix that.

Folds in stories 002 and 005 (012 is in local files, 015 in editing). As-is facts are pinned to commit c62d712; the proposal is marked as such · Reading time: 5 minutes · Prerequisites: MarDoc architecture

01 · WhyThe tree is the first thing a reader sees, and today it is noise

In a large repository the reader scrolls past dozens of open folders to find one file. The owner, 2026-10-29: "one that bugs me is the directories all being expanded when I visit a site". #151

02 · ContractThe tree, the selected file and the branch arrive in any order

Every visit, link and reload starts here, so the open folders must survive a reload without changing how the tree is fetched. A link names a file before the tree has loaded, and a repo opened with no branch starts on a guessed main (app-context.tsx:867). Storage is small and can fail. Sidebar.tsx:57

Sidebar

Draws the file tree and the branch selector; turns clicks into app-context calls. exists

Per-folder open state (one useState per node) and the branch dropdown state. Proposed: the expansion state for the current repo and branch.

Interfaces

Reads repoFiles, selectedFile, selectedBranch; calls openFile and setSelectedBranch.

Boundary

Does not fetch, route or write storage directly; app-context, github-api and expansion-store do.

Failure

A folder without children shows no rows when opened. Nothing else fails here.

app-context

Holds the repo, branch, tree and selected file; loads the tree; restores the last repo and opens links. exists

Owns

currentRepo, selectedBranch, repoFiles, selectedFile, the saved repo under mardoc_current_repo.

Interfaces

Sidebar calls it; it calls fetchRepoTree, fetchBranches, parseHash.

Boundary

Does not know which folders are open; the Sidebar does. #151 adds nothing here.

Failure

A failed tree load sets an error and an empty tree. The saved repo is not cleared (story 005, partial).

Source: app-context.tsx:834, story 005

github-api

Fetches the tree with one recursive call (cached by repo and ref) and builds the nested RepoFile[], the only source of folder paths. Defined in GitHub connection. github-api.ts:224

tree-expansion.ts proposed

The pure model of which folders are open. No React, no storage, no clock.

Owns

The rules: reveal a path, toggle a folder, collapse all, serialize, parse, cap the size.

Interfaces

Plain functions over a ReadonlySet<string> of folder paths. Imports nothing.

Boundary

Does not read the tree, storage or the URL; its callers do.

Failure

Total: parse returns an empty set for any bad input and never throws.

expansion-store.ts proposed

The adapter that keeps expansion state per repository and branch.

Owns

The key, the 20-entry and 200-path bounds, the eviction rule.

Interfaces

load(store, repo, branch) and save(store, repo, branch, set). The store is a parameter with getItem and setItem; production passes safe-storage.

Boundary

Does not know React or the tree. Folder rules stay in tree-expansion.

Failure

Unreadable or oversized data loads as empty. A failed write is dropped silently, as safe-storage does.

hash-router

Parses #/owner/repo/blob/branch/path into a route. Defined in L2 links and routing.

safe-storage.ts

A localStorage wrapper that returns null or does nothing when storage is unavailable. safe-storage.ts

05 · ProposedOne pure model, one adapter, and a controlled Sidebar (#151)

All of this is proposed; nothing here is built. Folders start collapsed, a link expands only its path, and the choice survives reloads.

The model: src/lib/tree-expansion.ts

State is a set of expanded folder paths, such as docs and docs/design. An empty set means everything is collapsed.

FunctionBehaviour
reveal(state, filePath)Adds every ancestor folder of filePath. Paths that start with __ (new or local files) add nothing.
toggle(state, folderPath)Adds the folder if absent, removes it if present.
collapseAll(state)Returns the empty set.
serialize(state) / parse(text)A sorted JSON array of paths. parse accepts only an array of strings, drops other items, keeps at most 200 and never throws.

Everything returns a new set; nothing mutates. There is one set and no "collapsed" list: a revealed folder is stored as expanded, so a later click collapses it like any other.

The adapter: src/lib/expansion-store.ts

  • Key: one localStorage key, mardoc_tree_expansion, holding {"owner/repo@branch": ["docs","docs/design"], ...}. It matches the existing mardoc_* keys.
  • Bound: at most 20 repo-and-branch entries and 200 paths per entry, so the value stays under about 32 KB (hypothesis: 200 paths of about 60 bytes is 12 KB per entry before the cap on entries). A save re-inserts its entry last; beyond 20 entries the first is dropped. Beyond 200 paths the earliest in sorted order are dropped. Both limits are design choices, not measurements.
  • Injected store: load(store, repo, branch) and save(store, repo, branch, set) take an object with getItem and setItem. The Sidebar passes safe-storage. Tests pass a plain object.

The Sidebar: no more per-node state

  • FileTreeItem loses useState(depth < 2) and takes expanded: ReadonlySet<string> and onToggle(path). The depth prop stays for indentation only.
  • The Sidebar holds one useState for the set. One effect on the resolved key loads the set from the store and then applies reveal(set, selectedFile.path). A second effect on selectedFile.path applies reveal alone. A third saves the set when it changes.
  • The key is the ref of the loaded tree, which app-context sets with repoFiles, not selectedBranch. A repo opened with no branch first shows main and later switches to the real default (app-context.tsx:867, :877-878). While the ref is unresolved, reveal applies in memory only and nothing is loaded or saved, so no phantom o/r@main entry evicts a real one.
  • A scroll effect calls scrollIntoView({block: "nearest"}) on the selected row once per selection, after the row exists. A click on a visible row scrolls nothing.
  • An optional "Collapse all" button in the Files header calls collapseAll.
  • The PR changed-files tree keeps its own useState(true); #151 does not change it.

Deep links

A link such as #/o/r/blob/dev/a/b/c.md reaches the Sidebar as selectedFile.path = "a/b/c.md" and, through activateRepo, as the key o/r@dev. The Sidebar needs no router code and no tree: reveal works from the path alone, so it does not matter whether the tree or the file arrives first. How links are parsed and written is owned by L2 links and routing. #151 adds no hash format and no hash writes.

06 · JourneysThree visits, step by step

Read each journey in order; with JavaScript off every scenario stays visible.

"I open mardoc.app with no link."

  1. app-context finds no hash, reads the saved repo from mardoc_current_repo and opens it on its default branch. app-context.tsx:1100
  2. github-api returns the nested tree from one recursive call, or from the cache. github-api.ts:224
  3. expansion-store (proposed) loads the set for owner/repo@main: empty on a first visit, the saved folders otherwise.
  4. Sidebar renders the top-level rows only on a first visit. No file is selected, so nothing is revealed or scrolled.

"I open a link to a/b/c.md on branch dev."

  1. hash-router parses the hash into repo, branch dev and path a/b/c.md. L2 links and routing
  2. app-context sets selectedFile to that path, activates o/r on dev and starts the tree load. app-context.tsx:908
  3. expansion-store (proposed) loads the set for o/r@dev.
  4. tree-expansion (proposed) adds a and a/b to that set.
  5. Sidebar renders the two folders open, highlights c.md, scrolls it into view once the tree arrives, and saves the set.

"I expand docs, open another file, reload."

  1. Sidebar calls toggle for docs when the folder row is clicked.
  2. tree-expansion (proposed) returns a new set that contains docs.
  3. expansion-store (proposed) serializes the set and writes it through safe-storage, last among its 20 entries.
  4. app-context opens the other file. Its ancestors are added; docs stays open.
  5. Sidebar, after the reload, loads the same set for the same key and renders docs open.

07 · FailuresBad data and big trees degrade to "collapsed", never to an error

CaseWhat happensRecovery
Corrupt storage: invalid JSON, a wrong shape or a non-array valueparse returns the empty set; the Sidebar shows a collapsed tree. Nothing throws.The next save overwrites the entry.
Storage unavailable or fullsafe-storage returns null or drops the write. Expansion works for the session and is not kept. safe-storage.tsNone needed.
A renamed or deleted folderThe old path stays in the set and matches no folder, so it does nothing. The renamed folder starts collapsed. The 200-path cap bounds the leftovers."Collapse all" empties the set.
A huge repositoryCollapsed folders do not mount their children, so a first visit renders only the top level. The tree fetch is unchanged and still ignores truncated, so a very large repo can show a partial tree (existing gap; Q-RB-3).The cap keeps storage under about 32 KB however many folders are opened.
A link to a path not in the treereveal still adds its ancestors, which match nothing, and no row scrolls. The viewer shows the file-load error as today.None needed.

08 · RulesThe model stays free of I/O, and CI says so

09 · ProofThree checks show it works; the full list goes in the slice plan

  • reveal unit tests: a/b/c.md gives exactly a and a/b, synthetic __ paths give nothing, and corrupt or oversized storage parses to a bounded set without throwing.
  • A Sidebar component test: toggle, open another file and remount keeps the folder open; a branch switch loads its own set; a provisional main writes nothing.
  • The LR-12 check fails when tree-expansion.ts imports a module or names localStorage.

Test names cite F-n once #151 has a row (Q-RB-7). Status: planned.

L2 · Subsystem · As-is at c62d712 · Part of MarDoc architecture (L1)

A reviewer selects text in a rendered HTML page and the comment lands on a source line

Implements: inline review comments on HTML files. The app tags each source element with its line, the iframe reports the selection, and the parent posts it as a review comment.

Describes the code at c62d712, with known gaps. Old story: 033 (status: Partial, see feature index). Reading time: 5 minutes.

01 · WhyHTML documents get the same review flow as Markdown

The product promises "Markdown and HTML" review; the iframe makes HTML selection impossible from the parent, so a small bridge exists. 033 value

Teams review AI-generated HTML reports and slide decks. Without this part, a reviewer cannot comment on a passage in them.

02 · ContractThe selection happens in a frame; the comment must land on a source line

GitHub anchors a review comment to lines of the file, but the reviewer selects rendered text inside an iframe the parent cannot watch. Markdown selects in the parent DOM and fuzzy-matches text to lines (mapSelectionToLines (github-api.ts:1000)). HTML must carry exact lines across the frame boundary and trust only what the frame may say.

03 · The partsSeven parts, one message across the iframe

HTML sourceLine taggerRendered iframeMessage listenerComment pipelineJump and markers hookComment locator

All components are described below.

Line tagger

Stamps every element with its 1-indexed source line.

Owns

The pure string pass injectSourceLineAttributes; data-mardoc-line, and with includeEndLines data-mardoc-end-line.

Interfaces

Source string in, tagged string out. Skips script, style, textarea and title bodies.

Boundary

Does not parse into a DOM or touch the iframe; the viewers do.

Failure

A tag it cannot see gets no line, so a selection inside it posts nothing.

Source: html-source-lines.ts:24 raw-text skip (html-source-lines.ts:166)

Rendered iframe

Shows the document and runs the injected scripts.

Owns

The live DOM, the document's own scripts, the injected selection and resize scripts.

Interfaces

srcdoc in; postMessage out to the parent.

Boundary

Does not hold comments or decide anything; the parent does.

Failure

A navigated-away iframe is detected and reported, not guessed at.

Source: DiffViewer.tsx:1120 HtmlViewer.tsx:358

Message listener

Turns an iframe message into a pending comment.

Owns

pendingSelection and its line range in the viewer's state.

Interfaces

Receives mardoc-html-selection, -rejected and mardoc-iframe-resize on window.

Boundary

Does not post the review; PRDetail does.

Failure

A rejected message clears the pending quote and shows a notice.

Source: DiffViewer.tsx:417-446 HtmlViewer.tsx:105-126

Comment pipeline

Queues the comment and posts the review.

Owns

PRDetail pending review; body prefixed with the quote.

Interfaces

onAddComment(0, body, text, startLine, endLine).

Boundary

Does not know the comment came from HTML.

Failure

Posting errors surface in the existing submit flow.

Source: DiffViewer.tsx:820 PRDetail.tsx:175

Jump and markers hook

Finds a stored comment in the live iframe, highlights it, and paints passive markers.

Owns

The inert source template, the loaded Document, highlight and marker cleanup.

Interfaces

Locates and highlights the passage in the rendered document; reports status text to the viewer.

Boundary

Does not choose lines; the locator does.

Failure

Reports why a jump failed and leaves the document unchanged.

Source: use-html-comment-jump.ts:13 html-comment-markers.ts:14

Comment locator

Maps a stored target and quote back to elements.

Owns

The status result: found, range, ambiguous, missing, hidden, outdated, file, unknown.

Interfaces

Source fragment, live document, CommentTarget, quote.

Boundary

Does not mutate the document or operate slides; the highlight and slide helpers do.

Failure

Returns a named status; it never invents a location.

Source: html-comment-location.ts:94

HTML source

The file text for the base or head revision. Owned by the PR file loader.

04 · As-isClaims at c62d712

  • The line tagger adds data-mardoc-line to each opening tag and skips raw-text bodies. html-source-lines.ts:24 raw-text skip (html-source-lines.ts:166)
  • The PR viewer tags both revisions with end lines, then builds the iframe srcdoc and appends the resize and selection scripts before </body>. DiffViewer.tsx:455 DiffViewer.tsx:470
  • The selection script fires on mouseup and touchend, walks anchor and focus up to the nearest tagged ancestor, and posts the min and max line. html-selection.ts:98-141
  • It refuses a selection that touches a removed diff node and posts mardoc-html-selection-rejected. html-selection.ts:120
  • The base revision has no selection script, and the parent ignores selections while it shows the base. DiffViewer.tsx:429 DiffViewer.tsx:470
  • The parent submits the posted range as is. Without a range it falls back to mapSelectionToLines, the Markdown path. DiffViewer.tsx:815-820
  • The comment body is the quote plus the text: > _"quote"_. PRDetail.tsx:175
  • Jumps and markers do not use messages. The hook locates the passage in the rendered document and validates against an inert template copy of the source. use-html-comment-jump.ts:15-40
  • The locator needs the stored line range or a quote. It returns a named status such as ambiguous or outdated, and never guesses. html-comment-location.ts:94
  • Numbered slide decks and template notes are revealed through the deck's own controls before highlighting. html-comment-slide.ts:6
  • The standalone file viewer (HtmlViewer) has the same selection path and no jump or markers. It keeps comments locally and posts them on "Submit as PR". HtmlViewer.tsx:105-126 HtmlViewer.tsx:171-200

05 · Trust boundaryMessages from the frame (details private, SEC-01)

The frame sends mardoc-iframe-resize, mardoc-html-selection and mardoc-html-selection-rejected; the parent sets the height, the pending quote and line range, or clears the quote. DiffViewer.tsx:409-448

Further message-trust detail is kept privately (SEC-01).

  • SEC-01 item. Details are kept privately.
  • Duplicate listener. DiffViewer and HtmlViewer each carry their own message handler; the base-view and rejected cases exist only in DiffViewer.
  • Dynamic content. Text built by script at run time has no tagged ancestor, so a selection in it posts nothing. Story 033 scoped this out.

06 · JourneysTwo requests, step by step

Read each journey in order; with JavaScript off every scenario stays visible.

"I select a sentence and comment"

  1. Line tagger stamps each element with its line when the PR file loads. DiffViewer.tsx:455
  2. Rendered iframe receives the selection on mouseup, finds the tagged ancestors and posts text and lines. html-selection.ts:98-141
  3. Message listener checks the source and stores the pending quote and range. DiffViewer.tsx:428-441
  4. Comment pipeline receives onAddComment when the reviewer submits, and queues it. DiffViewer.tsx:820

"I click a comment and see its passage"

  1. Comment pipeline supplies stored comments with target lines and quote.
  2. Jump and markers hook waits for the iframe load, then asks for the location. use-html-comment-jump.ts:44-60
  3. Comment locator matches the quote inside elements overlapping the lines and returns a status. html-comment-location.ts:94
  4. Jump and markers hook highlights the range, or reports why not. use-html-comment-jump.ts:57-65

08 · Clean architecturePure rules in the middle, DOM and frames at the edge

Pure: the line tagger (string to string), resolveSelectionSourceLines, and the locator's matching. Adapters: the injected script string (runs in the frame), the two message listeners, useHtmlCommentJump and the marker host (read the live DOM), and PRDetail (posts the review). No CI rule enforces this layout for these files today.

Proposed: one frame check. The shared messaging design (rendering §08) gives both viewers acceptFrameMessage (rules private, SEC-01), through one RenderedHtmlFrame listener. That removes the duplicate listener.

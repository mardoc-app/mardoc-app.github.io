Editing: a rich editor over Markdown text, saved as a new-file PR

Implements: the L1 Markdown editor card, as-is at c62d712. The reader edits in a rich editor or a raw code view. Markdown is the stored form, and the editor opens a PR to save.

Folds in stories 004, 018, 015, 019 and 026; statuses are in the feature index · Reading time: 4 minutes

01 · WhyReviewers fix a document where they read it

Editing turns a review tool into a propose-changes tool; until a save, the only copy of the edit is in the browser. 004

02 · ContractMarkdown in, the same Markdown out, and no edit lost

The rich editor holds HTML, not Markdown, so every save converts back. The text must survive that trip, or a save silently rewrites the file (018). Unsaved work must not vanish on a click (026), and a save must update an existing file, not create one.

All parts are described below.

Rich editor

Shows the document as formatted text and takes edits.

Owns

The TipTap document and the isDirty flag.

Interfaces

Input: Markdown via markdownToHtml. Output: getHTML(), then Turndown.

Boundary

Does not write to GitHub; the save handlers do.

Failure

Markup TipTap cannot hold is dropped when the document loads (018).

Editor.tsx:745

Code view

Edits the raw Markdown or HTML text, the escape hatch from the rich editor.

Owns

codeContent, a plain string in a textarea.

Interfaces

Toggle button. Entering converts with Turndown; leaving parses with Showdown.

Boundary

Does not recover text the rich editor already lost.

Failure

Leaving code view re-parses the text, so rich-editor normalisation applies again.

Editor.tsx:895 · 019

Markdown conversion

Turns Markdown into HTML for the editor and HTML back into Markdown.

Owns

Showdown options, the Turndown rule set, the list of kept HTML tags.

Interfaces

markdownToHtml (in Editor.tsx; proposed to move to the shared converter, LR-16) and createTurndownService() (in lib).

Boundary

Does not know about GitHub or the dirty flag.

Failure

HTML comments and table spans are lost (two it.fails tests).

turndown.ts:8 · Editor.tsx:198

Draft store

Compares the edit with the loaded text and keeps a copy in localStorage.

Owns

Key mardoc:draft:v1:{repo}:{branch}:{path}.

Interfaces

reconcileDraft(scope, baseline, markdown) returns {dirty}.

Boundary

Does not warn the reader; the guard does.

Failure

New and local files are never dirty, so the guard does not protect them.

draft-store.ts:113

Navigation guard

Asks before an action discards unsaved edits.

Owns

The dirty ref and the one parked question.

Interfaces

setEditorIsDirty(bool) in; guardNavigation(text, action) wraps each navigation. A beforeunload handler covers tab close.

Boundary

Does not decide what is dirty; the editor says so.

Failure

A second question replaces the first, which counts as cancel.

Save handlers

Pick the Markdown (code view text or Turndown output) and hand it to a save path.

Owns

PR title, target path, error text, the submitted-PR link.

Interfaces

Calls createFileAsPR, commitFileToPRBranch, or posts file:save in embed mode.

Boundary

Does not build requests; the client does.

Failure

Existing-file save sends a create request (EDIT-02).

Editor.tsx:1236

GitHub client

Makes the branch, the commit and the PR through Octokit.

Owns

Branch name new-file/{slug}-{time}, commit message, PR body.

Interfaces

Octokit REST from the browser; see the sign-in page for the token.

Boundary

Does not read the editor or the file's current blob SHA.

Failure

Any GitHub error reaches the reader as the thrown message.

04 · As-is at c62d712What the code does today

  • The rich editor is TipTap. A debounced 300 ms pass runs Turndown on getHTML() and compares it with the loaded Markdown. Editor.tsx:775
  • Markdown goes in through Showdown, then footnote and alert transforms. Editor.tsx:185
  • Turndown keeps details, summary, sup, sub, kbd, mark, media tags and others as raw HTML, and has rules for div and span attributes. turndown.ts:21
  • The toggle runs Turndown on entry and Showdown on exit. The rich editor is read-only while code view is open. Editor.tsx:895
  • Code view runs the same dirty check on every keystroke, and the Editor reports it through setEditorIsDirty. Editor.tsx:1864, app-context.tsx:225
  • File open, PR open, repo open, branch switch, reload and hash links all go through guardNavigation. When dirty, it parks the action and shows a confirm modal drawn by the provider. app-context.tsx:249, :938, :1183
  • "Submit Edits as PR" appears for a dirty, non-embedded, existing file. It calls createFileAsPR with the edited text. Editor.tsx:1604, :1256
  • createFileAsPR branches from the default branch, commits with createOrUpdateFileContents, opens a PR. github-api.ts:1124
  • Embed mode (VS Code) saves by postMessage to the host, not to GitHub. Editor.tsx:1277
  • New File opens an unsaved __new__/untitled.md; NewFileModal picks the path and saves it as a PR. An existing path is not warned about (story 015, Partial). app-context.tsx:953, Editor.tsx:1211

05 · Known gapsEditing is partial

The save path is the weakest part: it has not been proved to update an existing file. EDIT-02

  • EDIT-02 (story 004, Partial). The existing-file save calls createFileAsPR, which sends no blob SHA, so GitHub is expected to reject an update. The handler also appends .md to any path not ending in .md, including .mdx. Found by source review; no live write was run. github-api.ts:1158, Editor.tsx:1255. For contrast, applySuggestion reads the SHA before it updates. github-api.ts:921
  • Round trip (story 018, Partial). HTML comments and table colspan do not survive. html-roundtrip.test.ts:285, :294. The converter tests do not run TipTap.
  • Code view (story 019). Core toggle works. Syntax highlighting and auto-size are unverified.
  • Guard (story 026, Partial, DATA-01). New and local files are not tracked as dirty, and pending reviews have no equivalent recovery. draft-store.ts:113

06 · JourneysTwo requests, hop by hop

Read each journey in order; with JavaScript off every scenario stays visible.

“Fix a typo and send it as a PR”

  1. Rich editor takes the keystroke and fires onUpdate.
  2. Conversion runs Turndown on the HTML after 300 ms. Editor.tsx:777
  3. Draft store sees a difference, stores a draft, returns dirty.
  4. Guard receives dirty through setEditorIsDirty.
  5. Save handlers run Turndown again on click and pass the Markdown on.
  6. GitHub client creates the branch, commits, opens the PR, returns number and URL. The Editor shows the link and clears the draft.

“Fix a comment the rich editor hid”

  1. Code view opens: the rich editor turns read-only.
  2. Conversion gives Turndown output to the textarea. Edits run reconcileDraft per keystroke.
  3. Code view closes: Showdown parses the text.
  4. Rich editor receives it with setContent. Anything TipTap cannot hold is dropped here.

08 · Clean architectureThe conversion and the dirty rule are pure; the component mixes them with I/O

Today Editor.tsx (1,996 lines) holds both the rules and the effects, so no rule can be tested without React.

KindParts
Pure candidatesThe Turndown rule set (turndown.ts), the Showdown pipeline, the dirty comparison, the choice of Markdown source (code view text or converted HTML), path normalisation, branch-name and PR-body building.
AdaptersTipTap (editor), localStorage (drafts), Octokit (github-api.ts), postMessage (embed host), beforeunload and the confirm modal.
Where code mixes them(1) markdownToHtml and the Showdown instance live inside the component (Editor.tsx:185). (2) reconcileDraft returns the dirty answer and writes localStorage in one call (draft-store.ts:113). (3) The provider owns the guard rule and draws the modal (app-context.tsx:1183). (4) createFileAsPR chooses the branch name, message and PR body as well as calling the API (github-api.ts:1124). (5) The Turndown call is repeated at several sites in the Editor (785, 1153, 1250, 1284).
Proposed (Q-ED-3): a pure module in src/lib/editing/ holds the Turndown rules, the dirty comparison, the save-source choice and the PR plan. The clock comes from the caller. It is an entry in the shared pure-modules rule, LR-12. Markdown to HTML is not here: rendering owns that converter (LR-16).

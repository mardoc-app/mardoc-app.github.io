L1 · As-is at 2b94d90 · GitHub connection and credentials

One GitHub token, held in the tab, authorises every GitHub request

This page describes how MarDoc connects to GitHub at commit 2b94d90, checked on 2026-10-20. It records what the code does, not what it should do.

As-is baseline; no intent or judgement. Every claim cites code at the commit or a doc that matches it · Reading time: 8 minutes · Prerequisites: what a GitHub personal access token is

01 · WhyReviewers use their own GitHub token; there is no MarDoc account or server

MarDoc reads and writes GitHub on the reviewer's behalf, so it needs a GitHub credential, and it has no server of its own to hold one. README

Who benefits

Reviewers who open repository documents and pull requests in MarDoc, on the web or inside VS Code.

What it does

Uses one token per tab for every GitHub request, keeps a web token across page loads, and falls back to demo data without one.

Evidence

The README and the data and security reference describe this model; the code below matches it, except where noted. data-and-security.md

Covers the PAT flow, the VS Code embed token, storage and the GitHub client. Out of scope: repository loading and review flows, described on the system baseline.

02 · The problemA credential has to live in a tab that also renders untrusted documents

The tab that holds the credential also renders repository HTML, and both share one web origin. data-and-security.md

A reviewer's GitHub account issues a credential: a PAT pasted into MarDoc, or a token from the VS Code GitHub session. That credential grants access to repositories and pull requests. MarDoc runs in a browser tab on the mardoc.app origin, so the credential lives in that tab. Repository documents, including HTML with scripts, render in the same tab.

Three facts constrain the problem. The site is static, so there is no server-side session. GitHub grants exactly what the credential allows. next.config.js data-and-security.md

Under the hood: terms

PAT: a personal access token the reviewer creates on GitHub. Embed token: the token the VS Code extension sends in its init message. Demo mode: the state with no token, showing sample data. setup-github-pat.md

Key idea: the credential and untrusted documents meet in one browser tab, so rendered-content isolation matters (SEC-01; details are kept privately). SEC-01

03 · The piecesSix parts in the tab, two outside it

Token state owns the token. Settings and the embed listener feed it, localStorage keeps it, and the GitHub client spends it. app-context.tsx

Everything except GitHub and the VS Code extension runs in the reviewer's browser tab. No part runs on a MarDoc server: none exists at this commit. data-and-security.md

All components are described below.

Settings panel ● Exists

Where a reviewer pastes a PAT, connects and disconnects.

Owns

The token input field and the cached repo list (mardoc_user_repos).

Interfaces

Calls setGithubToken(token) on Connect and setGithubToken(null) on Disconnect.

Boundary

Does not store the token itself; token state does. Its help text says the token never leaves the browser and there is no server, which data-and-security.md calls inaccurate (Q-10).

Failure

An empty input does nothing. A wrong token is accepted here and fails later with a 401.

Source: SettingsPanel.tsx:97-110, 250-253 X-4

Token state (AppProvider) ● Exists

Holds the one GitHub token the tab uses, and switches the app between demo mode and a signed-in session.

Owns

React state githubToken and isDemoMode; the storage key mardoc_github_token.

Interfaces

setGithubToken clears repo, file and PR state, saves or removes the key, then calls initOctokit or resetGitHubSession. On mount it restores a saved token. applyInitData sets an embed token in memory only.

Boundary

Does not validate the token or call GitHub; the GitHub client does. Embed sender checks: RK-3.

Failure

If localStorage is unavailable, the token lives only until the tab closes. A 401 leaves the saved token in place.

Source: app-context.tsx:91, 144-146, 286-318, 321-331

localStorage ● Exists

Keeps the PAT across page loads on the mardoc.app origin.

Owns

mardoc_github_token, mardoc_current_repo, mardoc_user_repos, unencrypted.

Interfaces

Read and written through safeStorage, which swallows errors and returns null.

Boundary

Does not hold embed tokens; those stay in memory (SEC-01).

Failure

Private browsing or a full quota: reads return null and writes are dropped silently.

Source: safe-storage.ts data-and-security.md

GitHub client (Octokit + retry) ● Exists

Sends every GitHub request with the current token.

Owns

The module-level Octokit instance and the content, revision, tree, image and Mermaid caches.

Interfaces

initOctokit(token) replaces the instance and clears caches; resetGitHubSession() nulls it. A request wrapper makes up to 3 attempts (2 retries) for transient errors, waiting about 0.5 s then 1 s (±25%), and records a rate-limit pause. github-api.ts:58-78

Boundary

Does not decide what the UI shows; callers turn errors into messages with formatApiError.

Failure

401: no retry; callers show "your GitHub token is invalid or expired. Open Settings to re-authenticate." Rate limit: the client records a pause until the reset time (60 s if none is given) and rethrows; only PR comment refresh checks that pause (the 30 s timer, tab-visibility and post-write refreshes). PRDetail.tsx:133 rate-limit.ts:23-28

Source: github-api.ts:33-81 rate-limit.ts:19-45, 131-160

Embed init listener ● Exists

Receives the token and file from the VS Code extension when MarDoc runs inside its webview.

Owns

A module-level cache of the last init message, replayed on remount.

Interfaces

Listens for message events with type: "init"; posts ready to the parent with target *. Calls applyInitData.

Boundary

Sender checks are covered by RK-3 and F-16 (Q-11).

Failure

If no init arrives, the app stays in demo mode.

Source: app-context.tsx:96, 321-376 X-6

Rendered HTML iframes ● Exists

Show HTML documents in three viewers: HtmlViewer, the HTML path in DiffViewer and the RepositoryReference preview.

Owns

The rendered document, with injected resize and selection scripts.

Interfaces

Resize and selection messages with the app.

Boundary

Rendered-content isolation is SEC-01; details are kept privately.

Failure

Report security issues through the repository's private vulnerability reporting.

Source: HtmlViewer.tsx DiffViewer.tsx RepositoryReference.tsx SEC-01 X-2

GitHub REST and GraphQL

Holds repositories, pull requests and comments, and authenticates every request by token.

Owns

Repository content and review data.

Interfaces

HTTPS from the browser with the token in the Authorization header (set by Octokit).

Boundary

Grants what the token allows; MarDoc does not narrow it.

Failure

Returns 401 for a bad token, 403 or 429 for rate limits, 5xx for outages.

Source: github-api.ts:43-81

VS Code extension (mardoc-vscode)

Hosts MarDoc in a webview and passes in a token from the VS Code GitHub session.

Owns

Its own storage and the VS Code GitHub session.

Interfaces

Loads ${appBase}/?embed=true (default https://mardoc.app, overridable by the mardoc.appUrl setting); a wrapper script in the webview posts init to the frame with target *; the token is included only if a VS Code GitHub session exists, requested with the repo scope (extension.ts:111, 212-224, 261 at 41088d5).

Boundary

A separate repository; this page describes only the messages MarDoc receives.

Failure

Without the extension, nothing sends init and the app runs as a normal web page.

Source: mardoc-vscode src/extension.ts:111, 224, 261 at 41088d5 X-7

Key idea: there is one token per tab, and whoever calls token state last decides which token it is: Settings, a saved key, or an init message. app-context.tsx:286-331

04 · JourneysConnect saves the token; reload restores it; embed keeps it in memory

A pasted PAT persists in localStorage until Disconnect. An embed token is never written to storage. app-context.tsx:286-331

Read each journey in order; with JavaScript off every scenario stays visible.

“I paste my token and connect”

  1. Settings panel receives the pasted PAT on Connect and calls setGithubToken(token) on token state. SettingsPanel.tsx:97-101
  2. Token state clears repo, file and PR state, sets isDemoMode to false and writes the token to localStorage. app-context.tsx:286-298
  3. localStorage stores mardoc_github_token unencrypted. safe-storage.ts
  4. GitHub client builds a new Octokit with the token and clears its caches. github-api.ts:43-46
  5. GitHub receives the first repository requests with the token. github-api.ts

“I come back and I'm still connected”

  1. localStorage returns the saved token on mount. app-context.tsx:310-318
  2. Token state sets the token, leaves demo mode and calls initOctokit. app-context.tsx:312-317
  3. GitHub client is ready; the saved repository or the hash route loads next. github-api.ts:43

“I disconnect”

  1. Settings panel calls setGithubToken(null) and removes mardoc_user_repos. SettingsPanel.tsx:104-110
  2. Token state resets the GitHub session, removes the token and repo keys, and returns to demo data. app-context.tsx:299-307
  3. GitHub client drops the Octokit instance and clears its caches. Drafts and preferences stay. data-and-security.md:15 says the client is not reset; the code resets it (X-1). github-api.ts:33-41

“I open a file from VS Code”

  1. Embed init listener posts ready to the parent window with target *. app-context.tsx:370-373
  2. VS Code extension, through its webview wrapper script, posts init with the token (if a VS Code GitHub session exists), repository and file. extension.ts:261 (X-7)
  3. Embed init listener caches the message and calls applyInitData (sender checks: RK-3). app-context.tsx:353-361
  4. Token state sets the token in memory only (no localStorage write) and calls initOctokit. app-context.tsx:324-331

05 · FailuresErrors become messages; the saved token stays until the reviewer acts

No failure clears the token automatically; recovery is Disconnect or a new token in Settings. rate-limit.ts:131-160

Read each failure below; JavaScript adds selection and playback.

My token is wrong or expired

Reacts: GitHub client and the caller. You see: "your GitHub token is invalid or expired. Open Settings to re-authenticate." The token stays saved until you disconnect or replace it. rate-limit.ts:131-160

  1. GitHub returns 401. github-api.ts
  2. GitHub client does not retry a 401 and rethrows. github-api.ts:60-78
  3. Token state: the same AppProvider that runs the loads shows the message from formatApiError and keeps the token. app-context.tsx:469-553

GitHub slows me down or is failing

Reacts: GitHub client. You see: "GitHub rate limit reached. Resets in ~N minutes", or the request succeeds after a retry. rate-limit.ts

  1. GitHub returns 403 or 429 with rate-limit headers, or a 5xx. rate-limit.ts:84-120
  2. GitHub client records a pause until the reset (60 s if none) and rethrows, or makes up to 3 attempts for a transient error with about 0.5 s then 1 s backoff. Only PR comment refresh checks the pause; other requests still go out. github-api.ts:58-78

My browser blocks storage

Reacts: localStorage via safeStorage. You see: connecting works, but you are signed out on the next load. safe-storage.ts

  1. localStorage throws; safeStorage returns null and drops the write. safe-storage.ts
  2. Token state keeps the token in memory for this tab only. app-context.tsx:286-318

Another window sends an init message

Reacts: Embed init listener. You see: nothing; the message is ignored. RK-3 Q-11

  1. Embed init listener applies init only in embed mode and only from its parent window (F-16, isTrustedInit). embed-init.ts
  2. Token state keeps the current token and file.

Key idea: the client retries only transient errors; a 401 goes straight to the reviewer. github-api.ts:58-78

The documented model trades a server for a credential that lives in the browser. data-and-security.md

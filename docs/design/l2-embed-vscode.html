MarDoc runs in a VS Code webview and takes its file and token from the parent

Implements: the L1 Embed init listener card and F-16, with F-19 next to it. With ?embed=true, MarDoc takes a token and a file from init only when the message comes from its own parent window. Reload, images, save and links travel as small messages over the same channel.

Describes this repository's side only; the extension lives in mardoc-app/mardoc-vscode. No new issue. Reading time: 4 minutes · Prerequisites: sign-in L1 (credential and session, F-16, F-19)

01 · WhyThe webview is a second front end, and its door must have a lock

The VS Code extension hands MarDoc a GitHub token and a file through a message. The app accepts it only from its parent window. F-16

The app cannot open files in the webview, so it asks the host for file bytes, images and saves. The message channel is the whole interface, and about a dozen files touch it. story 017 story 030 story 040

03 · DiagramWhich parts talk to the host

All components are described below.

Webview and extension host

Holds MarDoc in <iframe id="mardoc" src="…?embed=true">, reads files, and answers messages. It lives in mardoc-vscode and is not verified here. A Playwright stand-in copies its shape.

isTrustedInit

Decides whether an init message may change state.

Owns

The rule: object data, type is init, ?embed=true, not top level, source === parent.

Interfaces

One pure function over five plain values.

Boundary

Does not read the DOM; the listener passes the values in.

Failure

Returns false and the message is dropped with no state change.

embed-init.ts:35

Embed listener

Wires the gate to the app: applies an accepted init, caches it, and posts ready.

Owns

Module-level vsCodeInitData cache, isEmbedded, the open local file.

Interfaces

Window message events in; credential module and React state out.

Boundary

Does not hold the token; the credential module does.

Failure

Any other init is ignored. No host, no init: demo data stays.

app-context.tsx:637

Reload bridge

Asks the host to re-read the open file and applies the answer.

Owns

Message shapes, the path match, the dirty rule for watcher pushes.

Interfaces

Sends file:reload; receives file:content.

Boundary

Does not watch files; the extension does.

Failure

Wrong file or bad shape: rejected and logged. A watcher push over unsaved edits is not applied.

embed-reload.ts:27 · app-context.tsx:709

Image bridge

Turns ![](./a.png) into a data URL by asking the host for the bytes.

Owns

Pending requests by requestId, a 5 s timeout (bridge:73).

Interfaces

Sends file:read-image; receives file:image-data or file:image-error.

Boundary

Does not touch GitHub images; loadAuthenticatedImages does.

Failure

Timeout or error marks the image mardoc-image-failed.

embed-image-bridge.ts:73 · github-api.ts:1411

Save and open links

Two one-way messages the webview cannot do itself: write the file, open a link.

Owns

Nothing; each call posts and goes on.

Interfaces

file:save from Editor; open-external from openExternal.

Boundary

Does not get an acknowledgement; the host owns the write.

Failure

A host that ignores them loses the save silently.

Editor.tsx:1277 · open-external.ts:4

Embed key handlers

Capture-phase Cmd/Ctrl+C and Cmd/Ctrl+Shift+R, active only when embedded.

Owns

The copy fix (execCommand("copy") while the selection is intact) and the reload trigger.

Interfaces

Document keydown; calls requestEmbedReload.

Boundary

Does not change keys outside embed mode.

Failure

VS Code can swallow keys before the iframe; the top-bar button is the sure trigger.

copy :148 · reload :729 · button:247

Credential and session

Keeps the token in memory. An accepted init becomes the connect-embed event. Defined in sign-in L1.

Rendered HTML iframe

Shows rendered HTML documents. Defined in L2 rendering.

04 · As builtWhat the code does at c62d712

  • Embed mode is read from ?embed=true after mount, and an accepted init also sets it. app-context.tsx:116 :641
  • An accepted init with a token calls setCredential({kind:"embed"}) and dispatches connect-embed; with fileName and fileContent it opens __local__/<path> and leaves demo mode. app-context.tsx:644
  • The listener caches the last init in a module variable and replays it on remount only when the URL says embed. It posts ready whenever the page has a parent. :685 :697
  • With an embed token the session starts as embed, not "sign in again". session.ts:51
  • Reload: button, command palette entry and shortcut share requestEmbedReload, which runs the unsaved-changes guard first. app-context.tsx:709 page.tsx:139
  • The sidebar opens on the PR tab and shows "Changed Files" in embed mode; the Save-to-disk button replaces Submit as PR. Sidebar.tsx:290 Editor.tsx:1591

05 · Known gapsTwo open, one waiting on the owner

  1. Unsaved-edit guard for local files is partial. Dirty tracking does not cover local files. DATA-01 features index
  2. No single outbound port. Five files call window.parent.postMessage and three add host listeners. See section 08.
  3. The real extension is unchecked. WP-2 increment 3 is the owner's: point the extension at a build and open a Markdown file and a PR. Demo data or no file means init was rejected. Cmd+C, the reload shortcut and local images are also unproven in a real webview. WP-2 increment 3

06 · JourneysTwo requests, step by step

Read each journey in order; with JavaScript off every scenario stays visible.

“Open design.md in VS Code”

  1. Embed listener mounts and posts ready to its parent. :698
  2. Host posts init with token, file name, path and text.
  3. isTrustedInit checks embed mode, not top level, source === parent. True. :35
  4. Embed listener caches the message and opens __local__/docs/design.md in the editor. :664
  5. Credential stores the token in memory; the session becomes connected. :646
  6. Image bridge asks the host for each relative image and swaps in a data URL. Editor.tsx:867

“An agent edits the file I am reading”

  1. Host watches the file and posts file:content with reason: "watch".
  2. Reload bridge checks the path matches the open file, then checks the editor is clean. If it is dirty, it logs and stops. :748
  3. Reload bridge sets the new text and bumps reloadNonce; the editor re-renders. :768
  4. Key handlers: for an explicit reload, Cmd/Ctrl+Shift+R (or the button) runs the discard guard first. :729
  5. Reload bridge posts file:reload; the answer is file:content with reason: "request". :42

08 · Clean designPure rules, thin adapters, one port to propose

The rules are already pure and tested. The wiring is scattered, and one small layout rule would collect it. LR-10 and LR-11

Pure: isTrustedInit, isReloadShortcut, shouldApplyFileContent, isBlockedByDirtyEditor, and the embed-only shortcut filter. Adapters: the two message listeners in app-context.tsx, the image bridge, postReloadRequest (in a mostly pure file), openExternal, and the save post in Editor. embed-reload.ts:27 keyboard-shortcuts.ts:58

Proposed: one host port. The shared messaging design (rendering §08) puts every host listener and post, including the image bridge, in src/lib/embed/host-port.ts. Its rules live in the pure messaging/protocol.ts. LR-15 enforces the layout by exact path; the injected frame scripts stay exempt because they run inside the frame.

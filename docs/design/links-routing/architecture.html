L2 · Subsystem · Part of MarDoc system, as-is (L1)

A link opens the same file in the same view, and old links keep working

Defines: the URL contract between a copied address and the app. One pure module parses and builds it; one adapter touches the address bar and storage.

Folds in stories 007, 009 and 021 (unchanged) · New work: issues #142, #143, #144 · Code as-is at c62d712 · Reading time: 4 minutes

01 · WhyA shared link must show what the sender saw

Today a PR file link names the file by its position in the list, and the view mode is not in the link at all. buildPRHash (:61-65) · viewMode state (:319)

When the PR changes, the numbers shift and the link opens the wrong file. The owner, 2026-10-29: "If I send a link, they may not see the view I was in" (#143). Reviewers also lose their view each time they open another file (#144).

02 · ContractThe link is read before the app knows the files or the screen

A link must name a file that survives PR changes and a view the recipient can show. The file list arrives only after the PR manifest loads, and only DiffViewer knows the file type and screen width. Every link already shared must still open.

03 · The piecesPure rules in the middle, two thin adapters at the edge

All parsing, building and precedence live in pure functions. Only route-adapter.ts reads or writes the address bar and the stored mode. Layout rules

All components are described below.

hash-router.ts

Turns a hash into a route and a route into a hash. Exists; extended by #142 and #143.

Owns

The URL grammar, percent-encoding and the file reference (path or index).

Interfaces

parseHash, build*Hash, resolvePRFile. Any module may call them.

Boundary

Does not touch window, storage or React; the adapter does.

Failure

A malformed link parses to {type:"none"}; the app shows "Invalid document link."

Source: hash-router.ts:23-51, app-context.tsx:1059

view-mode.ts

Names the view modes per file kind and picks one by precedence. Proposed.

Owns

The mode tokens and the precedence order.

Interfaces

parseMode, pickMode. Called by DiffViewer and the blob views, which know the file kind and the screen.

Boundary

Does not read storage, the URL or the viewport; its caller passes them in.

Failure

An unknown or unavailable mode falls to the next rule; it never throws.

Source: proposal below; mode state today is in DiffViewer.tsx:319-321

Link helpers

Classify and resolve the links inside a document. Exist; unchanged.

Owns

Anchor, relative and external classification; relative-path resolution.

Interfaces

classifyLink, resolveReviewLink. Called by DiffViewer, HtmlViewer and RepositoryReference.

Boundary

Does not build MarDoc URLs; hash-router.ts does.

Failure

An unsafe href resolves to blocked; the click does nothing.

Source: link-handler.ts:47, review-links.ts:7

route-adapter.ts

The only code that reads or writes location.hash and the stored mode. Proposed; today setHash and the listener sit inside app-context.

Owns

The hashchange listener, the write-loop guard, the storage key.

Interfaces

readLocation, publish(route, {replace}), onExternalChange, loadMode, saveMode. Called by app-context, page.tsx and PRDetail.

Boundary

Holds no rules; it calls the pure modules and moves bytes.

Failure

Storage blocked: no remembered mode, the app still works (as safe-storage (:5-11) does).

Source: app-context.tsx:286-293, 1103-1112

app-context.tsx

Opens the PR and file a route names. Exists.

Owns

Navigation state: current repo, PR, file index, error text.

Interfaces

navigateToHash, setSelectedPRFileIdx. Resolves the file reference once the manifest is known (proposed).

Boundary

Does not pick the view mode; DiffViewer does.

Failure

A missing file sets an error and keeps the PR open.

Source: app-context.tsx:1009-1022, 1057-1088

DiffViewer.tsx

Shows the file in one mode and builds links to other documents. Exists.

Owns

The on-screen mode; today it is local state that nothing stores.

Interfaces

Takes the link mode as a prop, typed per file kind (proposed); calls pickMode with the modes it can show; reports a user's mode change up.

Boundary

Does not read or write location; it builds hashes only through hash-router.

Failure

A mode the file or screen cannot show falls back to the kind's default.

Source: DiffViewer.tsx:319-321, 372-378, 976-989

Address bar

The browser's location.hash, the URL the user copies. It carries no secret; only the adapter touches it.

localStorage

Holds the proposed key mardoc_view_mode, one token per file kind, through safe storage. A missing or invalid value counts as none.

04 · As-isAt c62d712 the file is named by position and the mode is not shared

  • One module parses and builds hashes, free of React and window: hash-router.ts:23-69. Forms: #/o/r, /tree/{branch}, /blob/{branch}/{path}, /pull/{n}, /pull/{n}/files/{idx}; one query key, anchor. A bad escape yields none (story 021).
  • The PR file is a number, written only when idx > 0 (:61-65). app-context writes it before the manifest arrives (app-context.tsx:1009, manifest at :1020). An index past the list ends in "The linked PR file no longer exists" (:1022).
  • app-context's setHash remembers its own write so it does not re-navigate (:286-293). navigateToHash runs on load and on each foreign hashchange, and asks first when the editor is dirty (:1057-1112).
  • The mode is DiffViewer state: Markdown rendered | split | suggest | preview; HTML htmlViewMode (rendered | source) and htmlDiffMode (diff | head | base) (:319-321). HTML files show no Markdown buttons, and Side by Side is hidden below 768 px (:976-989). No mode is in the URL or in storage.
  • Other code reads location.hash directly: page.tsx:71-72 (sign-in target), SignInBanner.tsx:35, and PRDetail's comment jump, which cancels when the hash differs (PRDetail.tsx:81, :530).
  • Other code builds hashes: Copy link (page.tsx:84, no mode), and document links in DiffViewer.tsx:375, HtmlViewer.tsx:68 and RepositoryReference.tsx:41 (story 009).

05 · ProposedPath in the link, mode in the query, resolved once the data exists

The link names the file by path and the view by mode; the old index form still parses. Everything below is a proposal.

URL contract

route  = "#/" owner "/" repo [ "/" target ] [ "?" query ]
target = "tree/" branch
       | "blob/" branch "/" path
       | "pull/" number [ "/" file ]
file   = "file/" path           ; new (#142): path segments, each percent-encoded
       | "files/" index         ; legacy: still parsed, never built
query  = param *( "&" param )
param  = "anchor=" text | "mode=" mode      ; unknown keys ignored
mode   = md-mode | html-mode | blob-mode
md-mode   = "inline" | "split" | "suggest" | "preview"   ; Markdown file in a PR
html-mode = "diff" | "head" | "base" | "source"          ; HTML file in a PR
blob-mode = "preview" | "source"                         ; blob form: rich or rendered view, or code view
FormExample
Markdown PR file, by path, with mode#/acme/docs/pull/12/file/docs/my%20guide.md?mode=preview
HTML PR file on the base view#/acme/docs/pull/12/file/site/index.html?mode=base
Legacy, by index (still opens)#/acme/docs/pull/12/files/3
Blob in code view#/acme/docs/blob/main/docs/a.md?mode=source

Singular file/ avoids a clash with files/3: a file named 3 is file/3, an index is files/3. The path is the file's head path; a deleted file uses its base path. A token from another kind maps where it has a twin (inline ↔ diff, preview ↔ head) and is otherwise ignored.

Pure functions (src/lib/routing/)

type MdMode   = "inline" | "split" | "suggest" | "preview";
type HtmlMode = "diff" | "head" | "base" | "source";
type BlobMode = "preview" | "source";
type ViewMode = MdMode | HtmlMode | BlobMode;
type FileRef  = { kind: "path"; path: string } | { kind: "index"; index: number };
// HashRoute gains: file?: FileRef; mode?: ViewMode  (prFileIdx is replaced by file)

parseHash(hash: string): HashRoute
buildRoute(route: HashRoute): string          // build*Hash become thin wrappers
resolvePRFile(ref: FileRef | undefined, paths: readonly string[]):
  { ok: true; index: number } | { ok: false; reason: "no-such-path" | "index-out-of-range" }
parseMode(raw: string | null | undefined): ViewMode | undefined
pickMode<M extends ViewMode>(i: { link?: ViewMode; remembered?: ViewMode;
                               available: readonly M[]; fallback: M }): M

No React, window, localStorage or clock. hash-router.ts moves to routing/route.ts; the mode types live in routing/view-mode.ts. DiffViewer's prop is {kind: "md"; mode?: MdMode} | {kind: "html"; mode?: HtmlMode}.

Order of work on a cold link

  1. Parse. The adapter reads the hash; app-context parses it and opens the PR. It does not write the hash yet.
  2. File. When fetchPRFileManifest returns (app-context.tsx:1020), or at once in the warm branch (:1064), app-context calls resolvePRFile. A path wins, else an index, else the first file. Then it publishes the path form with replace.
  3. Mode. DiffViewer calls pickMode: the link's mode, else the remembered mode for this kind, else inline (Markdown) or diff (HTML). available comes from DiffViewer: no split below 768 px, HTML tokens only for HTML files.
  4. Writes. Only a click on a mode button saves the remembered mode. A link's mode is shown, not saved. A mode change replaces the address with history.replaceState, which fires no hashchange.

Existing readers and builders

  • The direct readers in §04 call readLocation(). Copy link builds through buildRoute with the current file and mode (#143). PRDetail's jump cancel compares parsed routes and ignores mode.
  • Old links: files/{idx} is read forever, never written, and opens whatever sits at that index today.

06 · JourneysTwo links, hop by hop

Each journey names the part that acts at every hop. All hops are proposed.

Read each journey in order; with JavaScript off every scenario stays visible.

“I send a link to the file I am reading.”

  1. DiffViewer shows docs/a.md; the user clicks Preview.
  2. app-context reports the path and mode to the adapter.
  3. hash-router builds #/acme/docs/pull/12/file/docs/a.md?mode=preview.
  4. route-adapter replaces the address with history.replaceState and saves preview.

“A teammate opens that link on a phone after the PR gained a file.”

  1. route-adapter reads the hash on load.
  2. hash-router parses path docs/a.md and mode preview.
  3. app-context opens PR 12, waits for the manifest, and resolvePRFile finds index 4. It then publishes the path form.
  4. DiffViewer mounts for index 4 with link mode preview and the modes a phone can show.
  5. view-mode picks preview: the link beats the remembered inline, and it is available. The same file opens in the same view.

08 · Clean rulesOne rule for every pure module, and one file for the address bar

  • LR-12, pure modules (proposed; this page owns it). scripts/check-layout.mjs gets one list of paths, each with an import allow-list. A listed file uses none of LR-10's banned globals (window, document, localStorage, location, Date.now, fetch and the rest; :175) and joins tsconfig.domain.json's include. Type imports are relative, because that config has no paths. Entries: routing/** except route-adapter.ts (siblings); tree-expansion.ts (none; repo browsing); pr-list.ts and the comment helpers (PR review); the pure part of editing/ (editing); messaging/protocol.ts (rendering).
  • Address bar. Only routing/route-adapter.ts may name location.hash, "hashchange" or history.. The same script checks it by exact path, after the call sites above migrate.

09 · ProofThree checks show it works; the full list goes in the slice plan

  • parseHash and buildRoute round-trip every form, mode and encoding (spaces, #, unicode), and file/3 differs from files/3.
  • One Playwright cold load of a path link to a PR that gained a file opens the right file in the linked mode. A unit test with a fake manifest cannot show the ordering.
  • Copy link on a blob in code view copies ?mode=source.

Failures stay small: storage, GitHub and fast clicks each have one pattern

Defines: the shared resilience patterns of the MarDoc browser app. Four named patterns, two more guarded parts, and the places the patterns are not yet kept.

As-is at c62d712; no behaviour changes · Reading time: 4 minutes · Prerequisites: MarDoc system baseline (L1)

01 · WhyFour patterns keep a browser-only app usable when storage, GitHub or the user's clicks go wrong

Other L2 pages link to these patterns by name instead of restating them.

Five old stories fold into this page: story 023, story 024, story 025, story 027 and story 029. The feature index rates 023, 024, 025 and 027 "Implemented core" and 029 "Partial" (features/README.md).

02 · ContractEvery failure lands in the reviewer's tab, and no server catches it

MarDoc has no backend, so a full disk, a GitHub outage or a late response is handled in the browser or not at all. Each pattern must keep the app usable and honest: a failed write or read must never look like success or an empty result.

03 · Diagram and patternsWho guards what between a screen and GitHub

Four pattern cards, then the link bubble and logging. Link to these names from other L2 pages: safe-storage wrapper, pause clock, one request wrapper, load generation.

All cards are described below.

Safe storage (pattern: safe-storage wrapper)

Every read and write of localStorage goes through three functions that never throw.

Owns

Nothing. It holds no state.

Interfaces

getItem returns null; setItem and removeItem return nothing.

Boundary

Does not report a failed write; the caller decides what a missing value means.

Failure

Private mode, denied access or quota: a read returns null, a write is dropped silently.

Source: safe-storage.ts:6 · safe-storage.ts:14 · story 023

Rate-limit pause and error text (pattern: pause clock)

One module-level pause time decides whether background GitHub work runs, and one function words every API error.

Owns

pausedUntil, last remaining and limit, and the credential kind.

Interfaces

markRateLimited, isRateLimited, updateFromHeaders, classifiers isRateLimitError, isTransientError, isAuthError, and formatApiError(error, context).

Boundary

Does not send or retry requests; the GitHub client hook does.

Failure

A 403 or 429 pauses for the reset time, or 60 s without one (rate-limit.ts:38). Remaining quota 0 pauses before the 403.

Source: rate-limit.ts:34 · rate-limit.ts:82 · rate-limit.ts:160 · story 024

GitHub client hook (pattern: one request wrapper)

Every Octokit request passes one wrapper that retries blips, marks rate limits and reports a dead sign-in once.

Owns

A retry loop of 3 attempts with jittered backoff (500 ms base, 4 s cap, github-api.ts:141), and an authErrorReported flag per credential.

Interfaces

Reads the caller's AbortSignal; calls markRateLimited; calls the hook set by setOnAuthError.

Boundary

Does not retry rate-limit errors or other 4xx errors, and does not check isRateLimited before sending.

Failure

Abort: the error passes through. 401 on a sign-in token: onAuthError fires once. 5xx or network: retry, then throw.

Source: github-api.ts:116 · github-api.ts:46 · abort.ts:2

Load generation (pattern: load generation)

A counter drops the result of any load that a newer load has replaced.

Owns

A counter per domain: repo, file, PR, tree, list and navigation guards in app-context; loadGen in the repo picker.

Interfaces

begin() returns isCurrent(); invalidate() makes all earlier loads stale. Abort controllers cancel the request as well.

Boundary

Does not cancel a request by itself; that is the abort signal's job.

Failure

A response that arrives late is dropped. A guard that is never begun protects nothing (see the gaps).

Source: staleness-guard.ts:34 · app-context.tsx:298 · app-context.tsx:309 · SettingsPanel.tsx:90 · story 027

Link bubble robustness

The link and image bubble never positions itself against a node that has left the page.

Owns

Local edit state; resets when the target changes.

Interfaces

Props target, containerRef, onDismiss. Dismisses on Escape or an outside click.

Boundary

Does not own the editor selection; the editor passes the target in.

Failure

Target removed from the DOM: renders nothing and schedules onDismiss. Near the right edge: the left offset is clamped to the container.

Source: LinkImageBubble.tsx:74 · LinkImageBubble.tsx:104 · LinkImageBubble.tsx:116 · story 025

Logging

Product code writes to the browser console and nothing else; no logger or redaction layer exists.

Owns

Nothing.

Interfaces

console.error in PR actions and API reads; console.log in the embed reload path.

Boundary

Does not reach the user; only a developer with devtools open sees it.

Failure

A failure logged and not shown looks like success or emptiness (AT-2).

Source: app-context.tsx:711 · PRDetail.tsx:306 · story 029

Screens

04 · As-isWhat the code at c62d712 does

  • Storage never throws. The token, the repo choice, the repo cache and the sign-in marker all go through the wrapper. app-context.tsx:411 · credential.ts:99
  • Only background work checks the pause. The 30 s comment refresh returns early when paused. PRDetail.tsx:133
  • A 401 on a sign-in token reaches the auth state once. The client calls the hook; app-context dispatches auth-error. github-api.ts:98 · app-context.tsx:601
  • Navigation invalidates in one call. invalidateNavigation bumps four guards, aborts the navigation and tree controllers and clears the loading flags. Unmount does the same for all guards and list controllers. app-context.tsx:309 · app-context.tsx:324
  • List loads cancel their predecessor. loadPRs and loadBranches abort the previous controller and check their guard before applying a result. app-context.tsx:776 · app-context.tsx:800
  • The repo picker uses its own counter. A key comparison is not enough because two PATs share the key "pat" (CR-9, M1 code review). SettingsPanel.tsx:90

05 · Known gapsSeven places where the patterns are not yet kept

  • A failed list looks like an empty one (AT-2). loadRepos ends in .catch(console.error); the picker then says MarDoc is not installed. SettingsPanel.tsx:102 · plan.md AT-2
  • Two retry implementations. withRetry in fetch-retry.ts has no caller in product code; the Octokit wrapper repeats the loop and imports only computeBackoff. fetch-retry.ts:29 · github-api.ts:116
  • Two more storage wrappers. draft-store.ts and image-path-config.ts each define a private safeStorage() instead of using the shared one. draft-store.ts:28 · image-path-config.ts:48
  • The pause clock gates one caller. The client hook does not read it, so foreground reads still go out during a pause. PRDetail.tsx:133
  • Logging is not clean. console.log calls remain in the embed reload path; story 029 stays "Partial". app-context.tsx:711 · features/README.md
  • Silent writes. A dropped token or draft write gives the user no signal (story 023: persistence may fail without recovery).
  • Swallowed read errors. fetchPRMarkdownCounts logs and returns an empty map (github-api.ts:465); the story 024 criterion for individual base and head content failures is open.

06 · JourneysTwo requests that touch every rule

Read each journey in order; with JavaScript off every scenario stays visible.

“I click PR 5, then PR 7 before 5 has loaded”

  1. Screens call the open-PR function twice.
  2. app-context calls invalidateNavigation, which aborts the first request and makes its guard stale. app-context.tsx:309
  3. staleness-guard hands the second load a fresh isCurrent; the first now returns false. staleness-guard.ts:37
  4. GitHub client hook sees the abort signal, throws the abort error and skips retry. github-api.ts:130
  5. app-context applies only PR 7's files; PR 5's late result is dropped. app-context.tsx:1005

“GitHub says I used my quota while I read a PR”

  1. GitHub client hook passes each response's headers to the pause clock; at remaining 0 it pauses. github-api.ts:106
  2. rate-limit.ts stores pausedUntil from the reset header. rate-limit.ts:90
  3. PRDetail skips the 30 s comment refresh while paused. PRDetail.tsx:133
  4. The reviewer clicks Refresh; the request is sent and fails, and formatApiError returns “GitHub rate limit reached. Resets in ~N minutes.” rate-limit.ts:167
  5. After the reset time, isRateLimited clears the pause and background refresh resumes. rate-limit.ts:42

08 · Clean architecturePure rules in the middle, three thin adapters at the edge

PartRoleNote
staleness-guard.tsPureA counter closure. No I/O, no clock.
Classifiers in rate-limit.tsPureisRateLimitError, isTransientError, isAuthError read only their argument.
formatApiError, pause clockDomain with module stateReads Date.now() and module variables, so tests set the clock. It is not pure.
safe-storage.tsAdapter: browser storageThe only place that may touch localStorage (proposed LR-19).
Hook in github-api.tsAdapter: GitHubOwns retry, abort and the 401 report. The domain never imports Octokit.
app-context.tsx refsAdapter: ReactHolds the guard instances and controllers.

Proposed (not yet in design.md). Two layout rules that CI checks:

  • LR-19. Only safe-storage.ts touches localStorage.
  • LR-22. Product code in src/ has no console.log.

Two conventions that review checks: every async load that sets UI state begins a load generation and takes an abort signal; a failed load sets an error state, never an empty result (AT-2), and its text comes from formatApiError.

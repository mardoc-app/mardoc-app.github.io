Rendering turns repository text into the page a reviewer sees

Implements: the HTML viewers card of the L1 and the Markdown rendering that the editor and PR review share. As-is at c62d712. This page owns the rendering security findings, the shared messaging design and the Markdown converter; other pages link here.

Reading time: 4 minutes · Prerequisites: MarDoc L1 baseline

01 · WhyReviewers read rendered documents, so rendering must show repository content faithfully

Every PR review shows repository content as Markdown, diagrams or live HTML. RK-1

Stories folded in: 006, 022, 031, 032, 041 (statuses: features index).

02 · ContractShow repository content as it will look when published

Reviewers need a document to look as it will when published: HTML with its scripts, Markdown with raw HTML, diagrams with links. Isolation of rendered content is a security item whose details are kept privately (§05).

03 · Diagram and partsSix parts: three on the Markdown side, three on the HTML side

Markdown-side parts transform strings and DOM in the tab; HTML-side parts build a document that an iframe runs. Design

Markdown renderCode highlightMermaidHTML viewersHTML inline diffRendered HTML iframe

All components are described below.

Markdown render

Turns Markdown into HTML for the editor, the PR diff and the PR description.

Owns

Showdown settings, alert and footnote transforms. diff-blocks.ts:119

Interfaces

Diff: blockToHtml, inserted as HTML. Editor: its own converter, then TipTap setContent. Editor.tsx:185

Boundary

Does not render HTML documents; those go to the HTML viewers.

Failure

Unsupported syntax renders as plain text.

Code highlight

Colors fenced code with lowlight's common grammars (story 006).

Owns

Token spans; diff markers kept across tokens. highlight.ts:98

Interfaces

Diff: highlightCodeBlocks(html) string to string. Editor: CodeBlockLowlight. Editor.tsx:752

Boundary

Does not load languages beyond common.

Failure

Unknown language: the block returns unchanged (highlight.ts:118).

Mermaid

Renders mermaid blocks as SVG in the active theme (stories 022, 032).

Owns

Lazy mermaid import, light and dark variables, one render queue, a 64-entry cache. mermaid.ts:50

Interfaces

Diff: renderMermaidBlocks(container) swaps pre for inline SVG. Editor: preRenderMermaid(html) yields an img with data-mermaid-source; Turndown restores the fence. turndown.ts:88

Boundary

Renders mermaid blocks only; other diagram formats stay as code.

Failure

A parse error leaves the code block as is (mermaid.ts:196).

HTML viewers

Prepare an HTML file for display: rewrite relative assets, tag source lines, inject scripts (story 031).

Owns

The srcdoc string. HtmlViewer.tsx:89

Interfaces

Three hosts: HtmlViewer, DiffViewer's HTML path and RepositoryReference. Helpers: html-assets.ts:5, html-source-lines.ts:1.

Boundary

Does not change the document beyond assets, line tags and the review scripts.

Failure

A broken document renders as the browser parses it.

HTML inline diff

Merges base and head into one rendered document with word, block and SVG marks (story 041).

Owns

Anchor matching, markers, removed-content cleanup. html-diff.ts:56

Interfaces

buildHtmlDiff(base, head) returns html, changes, hiddenChanges. Navigation: html-diff-navigation.ts:26.

Boundary

Compares static structure and text only; CSS, script output and pixels are not compared. story 041

Failure

Moves can show as delete plus add. Removed nodes lose scripts, on* attributes and ids (html-diff.ts:89).

Rendered HTML iframe

Runs the document's own CSS and scripts inside the tab.

Owns

Nothing. It is a browser feature; its settings are in the three hosts.

Interfaces

postMessage to the host for resize and selection. HtmlViewer.tsx:108

Boundary

Isolation is a security item, details private (§05).

Failure

A document that throws or loops affects only its frame and tab responsiveness (Q-RE-4).

06 · JourneysTwo requests that touch every part

Read each journey in order; with JavaScript off every scenario stays visible.

“Show this Markdown file's diff.”

  1. Markdown render converts each changed block to HTML with blockToHtml. diff-blocks.ts:139
  2. Code highlight colors fenced code in that string. DiffViewer.tsx:105
  3. Mermaid replaces mermaid blocks with SVG after the DOM commits. DiffViewer.tsx:396

“What changed in this page?”

  1. HTML viewers prepare base and head sources with line tags and asset URLs. DiffViewer.tsx:454
  2. HTML inline diff builds one annotated document. html-diff.ts:56
  3. Rendered HTML iframe shows it; the toolbar steps through changes. DiffViewer.tsx:1116

08 · Clean architectureOne message protocol, two adapters, one converter

The transforms are pure; the mermaid library, iframe hosts and TipTap are adapters. Today the sandbox string and srcdoc are built in three places; one shared frame component removes the duplication.

Messaging (proposed; this page owns it).

  • src/lib/messaging/protocol.ts, pure (an LR-12 entry), validates every inbound message on both channels (rules private, SEC-01).
  • Two adapters call it. RenderedHtmlFrame owns the child channel: sandbox, srcdoc, injected scripts and the listener, for all three hosts (HTML comments). src/lib/embed/host-port.ts owns the parent channel, including the image bridge (embed).
  • LR-15 (one layout rule, exact paths in check-layout.mjs): <iframe only in RenderedHtmlFrame; addEventListener("message" only in the two adapters and auth/sign-in-window.ts; parent.postMessage only in host-port.ts and the injected frame scripts html-selection.ts and iframe-resize.ts.

LR-16, one Markdown converter (proposed; this page owns it). src/lib/markdown/to-html.ts runs Showdown and the alert and footnote transforms. The diff, the editor and the PR description call it, and only that file may import showdown. Editing owns Turndown, the dirty rule and the save plan.

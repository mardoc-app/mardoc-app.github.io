04 · Phone viewerWidth alone picks the phone layout, and one hook owns that choice

Why it matters. On a phone, one document and thumb-sized controls matter more than desktop chrome (038). Status: partial.

Phone layout

Chooses mobile or desktop from the viewport width and swaps drawers and sheets for sidebars and rails.

Owns

The breakpoint: mobile at 767 px or less (use-viewport.ts:7).

Interfaces

useIsMobile() read by page, DiffViewer, Editor, HtmlViewer; Tailwind md: classes and one CSS media query for style.

Boundary

Does not detect the device or choose by touch; width only. The review flow stays in DiffViewer and PRDetail.

Failure

Before mount the hook returns desktop (use-viewport.ts:16); CSS hidden md:flex keeps the sidebar out of a phone's first paint (page.tsx:285).

As-is

  • One hook, two buckets, a matchMedia listener (use-viewport.ts:21).
  • Below 768 px the sidebar lives in MobileDrawer, opened by a hamburger and closed on selection (page.tsx:94, 181, 292).
  • Comments open in a BottomSheet, not the right rail; a fixed “Comment on selection” button replaces the floating toolbar (DiffViewer.tsx:1507, 1544, 1574). HtmlViewer hides its panel on a phone (HtmlViewer.tsx:367).
  • The editor outline becomes a drawer (Editor.tsx:1380). A wide-format toggle, kept in mardoc_wide_format through safe-storage, widens the document column at any width (use-wide-format.ts:6, story 008).
  • Reading type is 16 px at 1.65 line height under 768 px (globals.css:673); key buttons are 44 px tall (DiffViewer.tsx:285).

Known gaps

  • No swipe between PR files; no swipe code in src/ (038 unchecked box).
  • No tablet or “force phone” override; the hook has two values (use-viewport.ts:5).
  • The sheet's drag handle is decorative; it does not drag-dismiss (BottomSheet.tsx:24).
  • No visualViewport handling for the virtual keyboard (no match in src/; 038 open question).
  • Unsubmitted comments live in React state and do not sync across devices (038 status).

Journey: review a PR on a phone

  1. Reviewer opens a PR link on a 390 px screen.
  2. useViewport resolves mobile after mount.
  3. Page renders MobileDrawer; the hamburger opens navigation, and picking a file closes it.
  4. Reviewer selects text; MobileCommentButton appears and opens the comment input (DiffViewer.tsx:1574).
  5. Submitting the review is the desktop path (not re-run here).

Failures

  • Landscape at 768 px or wider: the hook returns desktop and the drawer unmounts (page.tsx:292).
  • Keyboard covers the sheet: unhandled (gap above).

05 · Local filesOne local file opens in the web app, and its relative images do not load there

Why it matters. A local note renders its text, but relative images break, so the local flow on mardoc.app misleads (042 Value; the story is committed at c62d712 as a plan, not as code). Status: planned (feature index); single-file open exists.

Local file open and image loader

Opens one file from disk under a __local__/ path and, inside VS Code, fetches its images from the extension.

Owns

The __local__/<name> path scope and the hidden file input (Sidebar.tsx:574).

Interfaces

Sidebar calls openLocalFile(name, text); Editor and DiffViewer call loadEmbedLocalImages(container, path).

Boundary

Does not see sibling files or write to disk; saving opens a GitHub PR (Editor.tsx:1606).

Failure

A rejected image gets mardoc-image-failed and an explanatory title (github-api.ts:1466).

As-is

  • Open file reads one file with FileReader.readAsText; accepts .md .mdx .markdown .html .htm (Sidebar.tsx:306, 576). No showDirectoryPicker or webkitdirectory exists in src/.
  • openLocalFile sets path __local__/<name> and opens the editor or HTML viewer (app-context.tsx:986).
  • Local files are never dirty and get no drafts (draft-store.ts:118, 147).
  • The editor leaves local image URLs relative (Editor.tsx:211).
  • loadEmbedLocalImages returns at once in a top-level tab (github-api.ts:1412). In the VS Code webview it strips __local__/, resolves the path, asks the extension over postMessage (5 s timeout) and sets a data: URL (1422, embed-image-bridge.ts:68).

Known gaps

  • On mardoc.app, relative images in a local file stay broken; no code handles it (the 042 problem).
  • No folder open; none of 042's eight criteria is built.
  • No write-back to disk; 042 defers the File System Access API.

Journey: open a note with a picture in the web tab

  1. Reader clicks the open-file button in Sidebar and picks note.md.
  2. FileReader reads the text; openLocalFile opens __local__/note.md.
  3. Editor renders it and leaves ./images/a.png relative.
  4. loadEmbedLocalImages returns at once; the browser resolves the path against mardoc.app and the image does not load.

Failures

  • Extension does not answer in 5 s: the bridge rejects; the image shows the failed placeholder (embed-image-bridge.ts:78).
  • Extension cannot read the file: same placeholder, title names the path.
  • Top-level tab: silent no-op; no placeholder and no message.

06 · AIAI rewrites feedback drafts through a URL the user types; page translation does not exist

Why it matters. Reviewers can ask a model to make a comment clearer; the feature is optional and off by default, and reviewing never needs it (data-and-security.md, AI section). Translation would store translated pages as repo files (037); no translation code exists in src/ (the word appears only in mock data). Status: polishing built, translation planned.

AI feedback connection

Holds one OpenAI-compatible connection and sends one explicit draft to it for a rewrite.

Owns

The on/off flag, the URL and model, and the API key (feedback-ai.ts:5).

Interfaces

Settings tab “AI feedback” (SettingsPanel.tsx:186); FeedbackPolisher in PRDetail, CommentPanel, DiffViewer.

Boundary

Does not send repo or thread context, only the draft, and does not replace text until the user accepts (feedback-ai.ts:66).

Failure

Named errors; the draft stays unchanged (feedback-ai.ts:85).

Where the key lives and where requests go. The API key stays in memory (sessionConnection); localStorage gets only the URL and model (feedback-ai.ts:6, 38). The browser POSTs with Authorization: Bearer <key> straight to the URL the user enters (HTTPS, or HTTP on localhost); there is no default endpoint, so the endpoint's CORS policy decides (feedback-ai.ts:77, 21).

As-is

  • Request: 10,000-character draft limit, 30 s timeout, 128 KB response cap, no redirects, no cookies, no referrer (feedback-ai.ts:50, 68, 78).
  • URL with credentials, query or fragment is rejected (feedback-ai.ts:23).

Known gaps

  • No translation, sibling detection or staleness banner; all 037 phases are open.
  • 037 says keys go in localStorage and names Anthropic and OpenAI SDKs; the code keeps the key in memory and has no SDK. 037 is stale on both.
  • The connection code is named for feedback (feedback-ai.ts, mardoc_feedback_ai); a second use needs a rename (the AI connection proposal).
  • No per-repo opt-out; 037 proposes .mardoc.json.

Journey: polish a review comment

  1. Reviewer enables AI in Settings, enters URL, model and key, and clicks Save; nothing is sent (FeedbackAISettings.tsx:37).
  2. Reviewer types a draft and clicks Polish feedback.
  3. polishFeedback POSTs {style, draft} to the endpoint.
  4. FeedbackPolisher shows the rewrite beside the original; the draft changes only on Accept (e2e test).

Failures

  • 401 or 403: “rejected this connection”; 429: “rate limited” (feedback-ai.ts:87).
  • Timeout at 30 s: “Your draft is unchanged” (feedback-ai.ts:100).
  • CORS or network error: “Could not reach the AI endpoint” (feedback-ai.ts:102).
  • Page reload: the key is gone; the user types it again.

07 · Clean designEach capability gets one seam, so the unfinished stories add an adapter, not a rewrite

Three proposals; all are renames or moves behind existing behaviour. None is built, and none is a CI layout rule.

ProposalWhat changesWhy
Viewport seamKeep useViewport as the only layout seam. Add a test that pins the 767 px hook, the 768 px Tailwind md: and the CSS query to one value. If a tablet override is ever added (Q-MO-2), it lives in the hook.The breakpoint appears in three places (hook, CSS, Tailwind classes).
Local-image portMove loadEmbedLocalImages out of github-api.ts into a local-image module with one port, path to image URL, and two adapters: the VS Code bridge, which calls the image request in embed/host-port.ts (messaging design), and a folder source (042).An image loader for local disk sits in the GitHub adapter file (github-api.ts:1411); the path rule resolvePath stays pure.
AI connectionSplit feedback-ai.ts into an AI connection module (validate, store, key in memory, bounded fetch) and thin callers: polishFeedback now, translatePage later.Translation needs the same endpoint, key and limits; 037's phases 1 and 2 (siblings, staleness) need no AI and ship first.

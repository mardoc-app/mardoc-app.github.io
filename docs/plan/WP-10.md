## Goal

Freeze the three pure modules that WP-11, WP-12 and WP-13 build on:
`src/lib/routing/route.ts` (the URL grammar), `src/lib/routing/view-mode.ts`
(mode tokens and precedence) and `src/lib/tree-expansion.ts` (which folders
are open). They follow the contracts in
[l2-links-routing § Proposed](../design/l2-links-routing.html) and
[l2-repo-browsing § Proposed](../design/l2-repo-browsing.html). CI enforces
that they stay pure (LR-12). No user-visible behaviour changes in this WP:
`hash-router.ts` keeps today's exports for the current callers.

**Requirements proved:** NF-80; the unit acceptance checks of F-84, F-85,
F-88 and F-89. The e2e checks of those rows belong to WP-11 to WP-14.

### Increment 1: the URL contract

Grammar (from l2-links-routing § 05):

```
route  = "#/" owner "/" repo [ "/" target ] [ "?" query ]
target = "tree/" branch | "blob/" branch "/" path | "pull/" number [ "/" file ]
file   = "file/" path        ; new: each segment percent-encoded
       | "files/" index      ; legacy: parsed, never built
query  = param *( "&" param ); param = "anchor=" text | "mode=" mode; unknown keys ignored
```

- `type FileRef = { kind: "path"; path: string } | { kind: "index"; index: number }`.
- `HashRoute` keeps `type`, `owner`, `repo`, `repoFullName`, `branch`,
  `filePath`, `prNumber`, `anchor`; gains `file?: FileRef` and `mode?: ViewMode`.
  It has no `prFileIdx`.
- `parseHash` keeps today's rules: a bad escape or unknown form returns
  `{ type: "none" }` and never throws. `mode` goes through `parseMode`; an
  unknown token is dropped.
- `buildRoute(route)` builds the path form only. It never builds `files/`.
  Query order is `anchor` then `mode`. A PR route with no `file` builds `#/o/r/pull/N`.
- `resolvePRFile(ref, paths)`: `undefined` → `{ ok: true, index: 0 }`; a path
  found → its index; a path not found → `{ ok: false, reason: "no-such-path" }`;
  an index in range → it; otherwise `"index-out-of-range"`. An empty `paths`
  with no ref returns `index-out-of-range`.
- The old builders (`buildRepoHash`, `buildBranchHash`, `buildFileHash`,
  `buildPRHash`) keep their signatures and output exactly, so DiffViewer and
  app-context are unchanged. `buildPRHash` still writes `files/{idx}` until
  WP-12 switches app-context to the path form.

### Increment 2: view modes

- Tokens: `MdMode = "inline" | "split" | "suggest" | "preview"`;
  `HtmlMode = "diff" | "head" | "base" | "source"`; `BlobMode = "preview" | "source"`.
  These follow Q-RT-1 and Q-RT-2 at their defaults.
- `parseMode(raw)` returns the token or `undefined` for anything else,
  including `null`, `""` and other case.
- Twins: `inline ↔ diff`, `preview ↔ head`.
- `pickMode({ link, remembered, available, fallback })` returns the first of:
  `link` if available; `twin(link)` if available; `remembered` if available;
  `twin(remembered)` if available; `fallback`. It never throws.

| link | remembered | available | fallback | result | proves |
|---|---|---|---|---|---|
| preview | inline | md all | inline | preview | F-88 link beats remembered |
| — | preview | md all | inline | preview | F-88 remembered beats default |
| — | — | md all | inline | inline | F-88 default |
| split | — | inline, suggest, preview | inline | inline | F-89 unavailable |
| bogus (parsed: undefined) | — | md all | inline | inline | F-89 unknown |
| head | — | md all | inline | preview | twin |
| base | — | md all | inline | inline | no twin |

### Increment 3: tree expansion and LR-12

- `reveal(state, filePath)` adds every ancestor folder: `a/b/c.md` adds `a`
  and `a/b`. A path starting with `__` adds nothing. A top-level file adds nothing.
- `toggle`, `collapseAll` as on l2-repo-browsing § 05. Every function returns a
  new set and never mutates its input.
- `serialize(state)` is a sorted JSON array. `parse(text)` accepts only a JSON
  array, keeps string items, drops the rest, keeps the first 200 in sorted
  order, and returns an empty set for any other input. It never throws.
- LR-12 in `check-layout.mjs`: a list of exact paths with an import allow-list
  each, checked against LR-10's banned globals: `src/lib/routing/route.ts` and
  `view-mode.ts` (may import `./route` and `./view-mode` only, type imports
  relative), `src/lib/tree-expansion.ts` (no imports). The address-bar rule
  (only `route-adapter.ts` names `location.hash`) is WP-12, after the call sites move.
  Update the header comment of `check-layout.mjs` to describe LR-12.

## Risks

- **What could break:** an encoding change in the old builders breaks
  existing shared links and story 009 document links. `hash-router.test.ts`
  and `review-links.test.ts` guard it and must not be edited.
- **The riskiest step:** `file/3` versus `files/3`. A dedicated test covers both.
- **Options not taken:** moving app-context to `file` now, because it couples
  this pure WP to navigation timing, which WP-12 owns.

# WP-11 slice plan (ACCEPTED 2026-11-04, owner approved in plan mode): folders start collapsed and remember their state (#151)

## Context

The owner, 2026-10-29: "one that bugs me is the directories all being expanded when I visit a site". Today every folder at depth 0 and 1 opens by itself (`useState(depth < 2)` in `FileTreeItem`, `src/components/Sidebar.tsx:57`), nothing reveals or scrolls to the open file, and nothing is remembered. WP-11 builds F-80 to F-83 from the accepted L2 page `docs/design/l2-repo-browsing.html` on top of WP-10's pure `src/lib/tree-expansion.ts` (merged).

Requirements (`docs/design/requirements.md`):
- F-80: a repository with no file selected shows only top-level entries.
- F-81: opening a file, by click or link, expands only its ancestors, highlights it and scrolls it into view.
- F-82: open and closed state persists per repository and branch across file opens and reloads.
- F-83: the Files header offers "Collapse all".

## One design gap found while reading the code (fixed in this WP)

The design says "the Sidebar holds one useState for the set". On phones `src/app/page.tsx:291-302` mounts **two** Sidebars: the desktop one (hidden by CSS) and the one in the drawer. Two separate states would each save, and the hidden one would overwrite the folders you opened in the drawer. The fix: one shared state for both. A small hook, `src/lib/use-tree-expansion.ts`, keeps one set per key in a module-level store and both Sidebars subscribe to it (`useSyncExternalStore`). Increment 2 updates the L2 page text to match. Behaviour is unchanged from the design; only where the state lives changes.

## Second point: the key needs the loaded tree's ref

app-context does not expose it today: `loadTree(repo, revision)` (`src/lib/app-context.tsx:848`) gets a SHA promise, and `selectedBranch` can be a guessed `main` (`:867`, `:899`). WP-11 adds `treeRef: string | null` to the context, set in `loadTree` together with `setRepoFiles(files)` and cleared with `setRepoFiles([])`. `loadTree` gains a `ref` argument; its four callers already have the ref in scope. This is a few lines in a file WP-12 also edits; WP-11 merges first or rebases, whichever finishes first. If the tree fetch fails, the ref stays null and nothing is saved.

## Increments

### 1. Store and key, no guessed `main` (riskiest: L2R-15)
- `src/lib/expansion-store.ts`: `load(store, repo, ref)` and `save(store, repo, ref, set)`. The store is a parameter (`getItem`, `setItem`); production passes `safe-storage`. Key `mardoc_tree_expansion` holding `{"owner/repo@ref": [paths]}`. At most 20 entries, the last-saved entry is newest and the oldest is evicted. Paths are capped at 200 through `tree-expansion`'s `parse` and `serialize`. Corrupt, wrong-shape or oversized data loads as an empty set and never throws.
- `treeRef` in app-context, as above.
- `src/lib/use-tree-expansion.ts`: the shared hook. With no `treeRef` (tree not loaded, demo mode, local file), `reveal` works in memory only; nothing is loaded or saved.
- **Proof:** unit tests `f82_store_*` (bounds, eviction, corrupt input, a plain-object store with no `localStorage`); a component test `f82_no_load_or_save_under_a_guessed_main`: open `o/r` whose default is `dev` with the tree still loading, and confirm no storage read or write for `o/r@main`, then a load for `o/r@dev` once the tree arrives; `f82_two_sidebars_share_one_state`. LR-12 is unchanged (`expansion-store` imports `tree-expansion` only).

### 2. Controlled tree: collapsed start, reveal and scroll (F-80, F-81, F-82)
- `FileTreeItem` takes `expanded: ReadonlySet<string>` and `onToggle(path)` in place of its own state; folders render `aria-expanded`.
- Reveal on `selectedFile.path` changes. Scroll the selected row with `scrollIntoView({block: "nearest"})` once per selection, after the row exists. On phones, the drawer's Sidebar also scrolls when the drawer opens. Clicking a visible row scrolls nothing.
- Existing e2e specs that open `docs/…` demo files relied on `docs` opening by itself. They get one explicit folder click through a shared helper `openTreeFolder` in `e2e/fixtures/helpers.ts`. Affected: `navigation-routing`, `critical-flows`, `per-file-comments`, `pr-image-stability`, `sign-in-ui`, `toolbar-parity`, and the helpers. This follows the intended change (F-80), not a weaker check.
- Update `docs/design/l2-repo-browsing.html` (the shared state and `treeRef`).
- **Proof:** `e2e/tree-expansion.spec.ts`, desktop and mobile:
  - `f80_repo_opens_with_folders_collapsed`;
  - `f81_deep_link_reveals_highlights_and_scrolls` (`#/o/r/blob/b/a/b/c.md` with a mocked tree: only `a` and `a/b` are open and `c.md` is highlighted and in view);
  - `f82_folder_state_survives_file_open_and_reload`.
  - Then the full Playwright suite.

### 3. Collapse all (F-83)
- A "Collapse all" icon button in the Files header (aria-label "Collapse all folders"), shown when the repository tree is visible.
- **Proof:** `f83_collapse_all_closes_every_folder` (desktop and mobile).

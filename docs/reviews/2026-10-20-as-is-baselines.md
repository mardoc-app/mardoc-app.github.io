## Verdict

1. **System page: fix first.** The structure, the SHA discipline and about 90% of the 120 or so citations hold. But eight Medium findings are wrong or misleading statements the owner would be accepting as fact, and one is a visible template artifact. None is a High. All are small text or diagram-label edits:
   - **BL-1:** raw `{d(Q,"Q-11")}` printed in the Embed bridge card.
   - **BL-2:** "retries up to 3 times" is 3 attempts (2 retries), and the 4 s backoff cap is unreachable.
   - **BL-3:** the "rate-limit pause" is honoured by exactly one caller, not by the GitHub client.
   - **BL-4:** "the view stays put on failure" is false for file, repo and PR opens.
   - **BL-5:** drafts do not go through `safe-storage` (author's flag b).
   - **BL-6:** only line-anchored comments are queued; general comments post immediately (author's flag a).

Intent language (BL-13) and an unsupported headline (BL-14) are Low. With those corrected it is accurate enough to accept.
3. **Cross-page consistency:** slugs match (`token-store`, `github-client` link targets exist: `#piece-token-store`, `#piece-github-client`). Names, ownership and who-reacts-to-401 differ (BL-11). No claim on one page is contradicted by the other beyond that, except the shared BL-2/BL-3 wording.

## Why and problem (adapted for as-is)

Written from each page alone, before opening sources.

- **Level:** both declare L1 (`<meta name="design-level" content="L1">`) and as-is at `2b94d90`. That matches step 0 for a baseline of existing code (an L1 for a whole system and an L1 for one cross-cutting concern). The eyebrow and takeaway name the SHA and the check date as `adoption.md` requires.
- **Why it matters (sys):** product managers, designers, writers and engineers read and review Markdown/HTML in GitHub without raw diffs. Evidence: README. Stated without a new value claim.
- **Why it matters (conn):** MarDoc has no server, so it needs a GitHub credential held in the tab. The h2 "reach their private repositories without a MarDoc account" goes beyond the cited README (BL-14).
- **The problem:** both pages state it without naming a solution component: the credential and the documents share one browser origin, and there is no backend to hold a session. sys adds PR/comment anchoring and the embed handshake. Both satisfy "problem before parts".
- **Headlines the owner would repeat:** sys h1 and the section h2s are claims, not labels (except the template-style "Trade-offs", "Design vs reality", "Cheat sheet", "Go deeper" headings, which are conventional). conn h1 "One pasted GitHub token, kept in the browser, signs every request" is a claim, slightly broader than true (Nit BL-23).
